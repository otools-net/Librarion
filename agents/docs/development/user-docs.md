# End-user documentation (docs/)

- User-visible changes (behaviour, settings, UI) go in `docs/`, kept user-oriented: `docs/user-guide/` (browsing,
  search, reading), `docs/administration/` (one page per admin section), `docs/opds.md` (connecting reader apps, per
  app), `docs/reference/` (rights, search syntax, settings levels), `docs/configuration.md`, `docs/upgrading.md`.
- Every web-UI function is documented, with a screenshot in `docs/images/` where it shows something (regenerated by a
  tool in `agents/tools/docs-screenshots/`, as SFE).
- `README.md` stays short: overview, quick start, links into `docs/`.
- Implementation facts go in `agents/docs/`, not in `docs/`.
- Routes are documented by OpenAPI, not in the docs: give every route `.WithName`, `.WithSummary`, `.WithTags`.
